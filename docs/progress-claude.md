## M4：检索、问答、日志与统计

两个 Sonnet 子 agent 并行完成后端和前端。Claude 先定接口契约，再核对代码、运行测试并在浏览器里联调。

### 实现要点

- 迁移 0004 新增 `qa_logs`，不保存用户 ID，也不保存拼接后的完整提示词。
- 检索在一条 SQL 里限定 `published`、`ready`、当前 `embedding_model` 和 `chunk_config`，以及可选课程，按余弦距离升序、片段 ID 打平取 Top-K（默认 5）。相似度 = 1 − 余弦距离。
- 证据门槛 `RETRIEVAL_MIN_SIMILARITY` 临时默认 0.40。低于门槛时直接返回证据不足，不调用云端。
- 演示模式零外部调用，摘录前 3 条合格片段。
- 云端模式的提示词和输出校验复制自 `scripts/spike_llm.py` 的 `spike-v2`，`backend/tests/test_qa_prompt.py` 断言两边一致。
- 返回前重新确认引用的资源仍是 `published` + `ready`。引用文字、标题和位置都从数据库构造。
- 查询嵌入模型在 API 进程启动后由后台线程加载。加载完成前，`/qa/ask` 返回 503 `retrieval_warming_up`。
- 每个用户每分钟最多问 10 次（进程内计数）。

### 一次未查明原因的故障

联调时出过一次 503 `retrieval_unavailable`（检索模型加载失败），对应 3 条 `internal_error` 日志。当时后端是用 .NET `ProcessStartInfo` 重定向输出启动的；改用 `Start-Process` 重启后正常。用同样的重定向方式单独加载、以及两个进程并发加载，都没能复现。目前只能确定它和那次的启动方式有关，具体原因未查明。
